日期：2026-08-19

范围：MHG zh-ko；反馈分析、通用 Skill/韩语语言层、MHG Profile 及开发验证。**未运行 LQE 或 Excel 回归。**

## 1. 文档目的与结论

本轮优化以四份人工反馈表为证据，目标不是让 LQE 模仿老师 Final 的全部措辞，而是区分并处理四类信号：

1. 可证明的准确性、语法、术语或明确不自然问题；
2. MHG 项目专属的旁白、角色语体、称谓、时代和场景规则；
3. 两种译法均可时的编辑偏好；
4. 源文/上下文不足及老师 Final 自身的反向错误。

核心结论：崔老师第三批的 E→F 字面改动率为 148/150，即 98.7%，但可进入“通用纠错原则或项目规则”讨论的只有 88/150，即 58.7%。其中客观问题 20 行，项目规范 68 行。58.7% 不是 LQE 错误率；68 行项目规范也不应上升为通用 Skill 规则。

本轮不新增后置 QA worker。确定性形式约束放在已有 correction builder、candidate publisher、suggestion verifier 和 artifact validator 中；语义与风格约束分别放在通用 Skill、韩语语言层和 MHG Profile 层。MHG 主 Profile 已从 `off` 切换为 `enforce`，并显式绑定 `ko.register@2`。

### 3.2 崔老师第三批：98.7% 与 58.7% 的拆分

E、F 均 150 行非空，148 行不同，原始字面改动率为 98.7%。54 行有 Note，94 个改动行没有 Note；有 Note 与空 Note 行的字符编辑距离中位数分别约为 45.3% 和 44.6%，说明 F 是全量编辑稿，不是只改明确错误的最小修订稿。

对 150 行逐行采用互斥主类：

| 主类 | 行数 | 比例 | 是否可直接称 LQE 错误 |
|---|---:|---:|---|
| `objective` | 20 | 13.3% | 可作为客观问题证据，但仍须保留源文、E、F 和理由 |
| `project_style` | 68 | 45.3% | 只能进入 MHG Profile；不能计为通用错误 |
| `preference` | 48 | 32.0% | 不计错，不转硬规则 |
| `source_context` | 5 | 3.3% | 不能归责 E；应 query、补上下文或人工选择 |
| `teacher_regression` | 7 | 4.7% | F 不可作为参考目标 |
| `no_change` | 2 | 1.3% | E=F |

百分比均按 150 行计算并四舍五入到小数点后一位。`objective + project_style = 20 + 68 = 88`，`88/150 = 58.666…%`，显示为 58.7%。这个指标表示“可吸收为通用纠错原则或项目规则的反馈”，不表示“LQE 错误率 58.7%”。

典型客观问题：

- R2174：铁线蕨被译成另一属植物 `봉의꼬리`；
- R2211：“言重了”被直译为 `말씀이 지나치세요`；
- R2225：`화초을` 助词错误；
- R2233：“惊喜”被处理为单纯“惊讶”；
- R2261：石制花箱被译成牲畜用 `돌구유`。

典型项目规范：

- R2152–R2154：第三人称取舍、旁白句尾及时态；
- R2168–R2170：主角内心独白与时代词；
- R2192：查理在该关系阶段使用 `-ㅂ니다` 体；
- R2202：旁白突然切换 `~다` 体；
- R2207 起：阿尔杰农在该场景的 해라체/하게체；
- R2237：谢尔盖对女主的称谓应保持 `부인`；
- R2244/R2261：同一石制花箱实体的跨行统一。

典型偏好：

- R2201：`와! 신난다!` → `신난다!`；

老师 Final 也会反向出错或漂移：

- R2176：`不引人注目 / 눈에 띄지 않다` 被改成 `눈에 거슬리지 않다`，变为“不碍眼”；

### 3.3 姜老师正文：反馈目标列必须内容对齐

534 行中 D→E 不同 518 行，字面改动率 97.0%。这里的 D 是 MT，E 是 Final/LQE，因此不能解释成“老师修改 LQE 97%”。

15 条 Note 中至少 14 条可逐字证明是在批评 D 列 MT：

- R9 Note 所述“受委屈的女人、不想争吵”只存在于 D，E 已恢复 `당장 집으로 따라와!`；
- R25 Note 所述 `용담 장미` 只存在于 D，E 已删除无来源花名；
- R81 Note 所述“从珍珠手袋拿先令行贿”只存在于 D，E 已恢复原意。

因此，反馈导入不能相信 Note 自由文本中的“LQE 建议译文”等列名描述，必须保存并核对 `review_target`，用 Note 提到的错误词、被审译文切片和实际列内容对齐。

空 Note 固定间隔抽样 105 行：明确残留 20（19.0%）、可争议过改 28（26.7%）、未见明显问题 57（54.3%）。典型问题说明 LQE 能修正严重 MT 错位，但容易越过必要编辑边界：

- R82：修补“我买单”时，把“暖暖身子”改成“清凉解渴”；
- R197：单数“她的崽子”变成复数 `자식들이`；
- R297：“给父亲一个吻”变成“打招呼”；
- R322、R387：事实确定度发生变化；
- R357/R359：“特派员”被一致地误成“记者”；
- R442/R452，另见 R461/R471：第二人称叙事漂成第一人称。

### 3.4 章、节标题：格式改动与内容改动必须分开

章标题 50 行全部发生 MT→Final 字面变化，其中 7 行有 Note；节标题 300 行全部变化，其中 12 行有 Note。合计 350 行 100% 字面变化，但 157 行（44.9%）只是统一为 `N장:` / `N절:` 等格式。剥离格式后，实际正文标题改动为 193 行，只有 19 行有 Note。

空 Note 正文改动系统抽样 44 行：明确纠错 5、合理标题编辑 18、近义偏好 10、需要上下文或有漂移风险 11。

Final 不能直接作为标题金标：

- 章 R27：“香蜂安胎”→“孕妇用药草”，植物信息被泛化；
- 节 R115：“七出”→“离婚理由”，文化概念被泛化；
- 节 R139：“以香入药”→“香气治疗”，动作关系改变；
- 节 R262：“棋手与棋子”→“棋盘上的棋子们”，棋手/棋子的对立仍被删除。

标题格式应由确定性 `title_mode` 负责，标题措辞仍受语义底线约束。格式命中不能计作 LQE 语言错误，也不能作为自然度模块的成功样本。

## 4. 已实现：确定性目标语形式门

### 4.1 设计边界

形式门是已有构建和发布链中的入选门，不是新增后置 QA：

- 只拒绝候选相对当前译文新引入的确定性形式缺陷；
- 当前译文已有缺陷不会阻断无关安全修改；
- 被拒绝的局部 edit 清空并降为待确认，不静默自动修正；
- 整句 reference suggestion 仍只供报告，不写入 corrected/export。

### 4.2 已实现检查

`scripts/lqe_target_form.py` 从 job-bound checks 资产加载 opt-in policy，当前通用检查包括：

- 首尾横向空白和连续 ASCII 双空格；
- 可选 NBSP/窄 NBSP 禁用；
- 圆括号、方括号和直双引号配对；
- 韩语直单引号配对；
- 只有显式 `mutation_gate: true` 的目标侧项目 regex；
- 对可解析局部 edit 的韩语宾格助词 `을/를` 收音边界回归。

MHG `projects/mhg/zh-ko/checks.json` 已显式启用 `target_form_gate`、NBSP、韩语直单引号和局部 `을/를` 边界检查；项目省略号 regex 同时进入 mutation gate。

局部 edit 的助词检查覆盖：

- 名词替换而助词留在 edit 边界外；
- 名词和助词在同一 edit 中但仍保留旧助词；
- 多个相邻 edit 合并后才出现的边界问题；
- 确定罪魁 edit 后只降级相关 edit。

R2245/R2247 的 `돌화분를` 是该机制要防止的真实反馈例；R2225 的 `화초을` 是原有 E 形式错误的例子。

### 4.3 有意保守的边界

整句 reference suggestion 不运行宽泛的 `ko_particle_edit_boundary`。整句缺少可靠 POS 和已解析局部 edit span，简单正则会把 `먹을 것→가을 것`、`시골마을`、`늦가을` 一类词尾误判为宾格助词。整句只运行通用形式项和项目禁用 regex；助词仍交 grammar/verifier 语境判断。

`은/는`、`이/가`、`과/와`、`로/으로` 也暂不进入确定性硬拦，避免把形态分析问题伪装成安全规则。

### 4.4 调用链静态复核

当前静态复核覆盖 correction build/verify、suggestion candidate 单批/分批构建、candidate validate、independent review、Final publish、报告加载和 CLI validate。观察到的生产入口均传入同一 job-bound `target_form_policy`；未发现漏参、NameError 或初始化期循环导入阻断。

这只是静态结论，不等于测试或 LQE 回归结论。

## 5. 已实现：snapshot/contract 兼容修复

### 5.1 问题

v2 job 已用 `project_asset_snapshot`、snapshot digest 和 job-bound runtime path 绑定项目资产。若 state revision 仍把 `checks_path` 当普通路径重新做裸文件快照，会出现两套资产身份口径：一套来自 v2 snapshot，一套来自路径现场状态，可能导致合法 job 被误判 stale，或检查资产变化没有按统一合同失败。

### 5.2 当前机制

`scripts/lqe_target_form.py` 的 policy loader 对 v2 资产合同执行：

- 校验 snapshot 结构；
- 要求 present checks 资产唯一；
- 解析 job-bound runtime path；
- 重新核对实际文件 SHA-256 与 snapshot；
- 资产缺失、重复、摘要不一致或 live path 与 snapshot 矛盾时 fail closed。

`scripts/lqe_split_contract.py` 的 revision snapshot 对 v2 `checks_path` 复用已验证 project asset snapshot 中的 checks 摘要，不再与普通 legacy 路径快照混用；v1 或没有 v2 asset contract 的旧 state 继续走原 `_asset_snapshot`，保持兼容。

风险边界：历史 v1 job 仍只读；旧 job 不能因为兼容 fallback 获得 v2 发布权限。任何最终兼容结论仍须由 contract/profile 测试确认。

## 6. Skill、语言层、Profile 与逐句上下文分层

### 6.1 通用 Skill 层

只放跨项目成立的合同和原则：

- 反馈必须有 `review_target`、`verdict`、`feedback_status`、`resolution_status`；
- 空 Note=`unknown`；Final 不自动成为 runtime gold；
- 源文是语义唯一依据，保持数量、人物、动作、因果、确定度、POV、状态变化和话语功能；
- 安全 edit 应局部、唯一且有证据；整句建议只供人工审校；
- 条件选择、源文疑误和文化改写进入 `human_choice_required`；
- 报表分开 exact edit、content edit、issue-backed correction 和 editorial rewrite。

通用 Skill 不登记“查理用什么句尾”“阿尔杰农叫什么”“维多利亚背景下月薪如何说”等项目事实。

### 6.2 韩语语言层

`target_languages/ko/eval_notes.md` 只放韩语通用判断边界：

- 敬语、半语、命令、称谓和代词必须依赖已验证 speaker/addressee/relationship/scene/text type；
- 中文礼貌词不自动等于韩语 `-요/-습니다`；
- 同一已验证 scene/group 内保持口吻连续；没有 scene/group 边界时不得只凭相邻行推断连续场景；
- 形式门的 `을/를` 仅用于可解析局部 edit；其他助词和整句形态交 grammar/verifier。

本轮新增 `target_languages/ko/register_v2.py`：

- `ko.register@2` 在原有 `politeness`/`ending_families`/`forbidden_families` 上增加 `person` 和 `tense`；
- 只对单分句、显式主语/主题代词和高置信词尾作确定观测；省略主语、多分句、未来/推量、复杂引语返回 `inconclusive`；
- v2 跳过单字句尾，避免把 `화분 상자` 的名词末字 `자` 误认成 haera；
- `ko.register@1` 保持原文件字节不变，SHA-256 仍为 `06e9317c486ccafd4e489a607c36e54d3584180af4f8fcba3f6bbef0341ef8ef`；
- 注册表默认仍返回 v1，只有显式绑定 `ko.register@2` 的 Profile 会启用新能力。

### 6.3 MHG Profile 层

项目资产保存：

- 近似维多利亚时代伦敦的时代词策略；
- 剧情旁白、内心独白和具体角色的 register rule；
- 人物关系阶段与称谓；
- 植物、物件、职位和场景实体；
- 已授权文化改写及其适用范围；
- 原始反馈来源和派生规则的 provenance。

Profile 通过 shadow/enforce 分层验证。单次 Final、偏好改写和未确认 Note 不进入 confirmed runtime rule。

### 6.4 Job/segment 上下文层

具体句段使用显式列或已验证 override：`speaker_id`、`addressee_ids`、`relationship_stage`、`scene_id`、`scene_tone`、`content_type`。人物姓名或台词内容不能临时充当关系推断器。

## 7. 已实现：MHG 剧情规则

以下项目风格规则已写入 `confirmed_rules.md`、`confirmed_context_decisions.json`、canonical 实体/关系资产和 `context_rules.json`；7.6 另行标明哪些客观证据只作 accuracy 审校输入，未被写成全局术语。运行时只启用 5 条 `confirmed` `ko.register@2` 规则；原 SG 归一化的 6 条未确认规则继续保持 `draft` 且由 v1 承载，不与 v2 正式规则混用。

### 7.1 剧情旁白

- 本批正文反馈要求剧情旁白使用过去时 `-았습니다/-었습니다` 系列，R2154 Note 明确写“旁白语体应统一为过去时 `~습니다`”，R2202 也把突然出现的 `~다` 改回 `~습니다`。
- 二人称旁白在动作主体可能不明时保留 `당신`，如 R2160、R2175、R2182；非必要第三人称尽量省略，如 R2152、R2153、R2163、R2187。
- 不得实现成“全删代词”：对白中的 `당신`、旁白中的 `당신`、人名复现和零主语分别判断。

旧的 confirmed “剧情旁白=haera/plain”已根据用户本轮 `go` 显式取代，不再与新规则同时激活。`person=second` 只对可识别的显式主语/主题代词作硬判断；人名/称谓不判为 third，自然省略主语时为 `inconclusive`。

### 7.2 主角内心独白

R2168 Note 明确把 R2168–R2170 视为同类：内心独白不使用对外礼貌的 `~습니다`，使用自然自言自语句尾，如 `~겠어`、`~든가`、`~겠는걸`。规则应绑定 `content_type=内心独白`，不能从说话人“我”自动推断所有台词都是独白。

### 7.3 角色语体

- 查理：R2192 表明当前关系阶段和场景中使用 `-ㅂ니다` 体，E 的 `-요` 等级偏低。规则必须绑定角色、受话人和关系阶段，因为 SG 说明其称谓会随亲密度变化。
- 阿尔杰农：作为年长且居高临下的六表叔，本批对女主统一 해라체；对谢尔盖等下位男性可用 하게체。证据包括 R2207、R2210、R2214–R2217、R2226–R2229、R2235、R2241。
- 谢尔盖：与女主当前关系下保持其已验证语体；不能因单句书面礼貌词临时升级或降级。

### 7.4 称谓与代词

- 女主称阿尔杰农为 `아저씨`，不用容易暗示亲叔的 `삼촌`，见 R2209/R2211 及 R2251；
- 阿尔杰农直接呼女主时优先自然呼格 `얘야`，避免机械 `조카야`，见 R2221；名词性“侄女/조카”不能一刀切删除；
- 谢尔盖称女主保持 `부인`，不单行漂到 `사모님`，见 R2237；

### 7.6 场景实体与跨行术语

- **已固化**：R2244、R2245、R2247、R2248、R2259、R2261 的花箱/石制花箱/石槽是同一实体，指定搬运场景中 canonical 为 `돌화분`，不得漂成包装箱或 `돌구유`。
- **已固化**：R2237 的 `부인` 作为角色—受话关系保存，不只做字符串一致性。
- **仅作 accuracy 证据**：R2174 证明铁线蕨不能译成另一属的 `봉의꼬리`；因 `공작고사리/아디안텀` 仍有项目选型，本轮未建全局单一 preferred term。
- **仅作 accuracy/一致性证据**：R2231/R2233 是同一培养土实体，可按句法使用 `배양토`、`흙 포대` 等指称，不能误成不同物件；本轮未建表面形唯一术语。
- **未跨项目泛化**：R2297 的警长职级依赖项目角色资料；在正式职级资产确认前，不因单行 Final 建全局映射。

### 7.8 规则实际命中路径

## 8. 已固化的反过度修改原则

本节已写入 `references/feedback_learning.md` 和 Skill 工作边界，作为反馈分类、规则入库和现有 checker/verifier 的必遵原则。本轮没有新增通用语义后置 worker，也没有宣称已实现新的全句双向蕴含 gate。

### 8.1 语义不变量

accuracy/suggestion 需显式保持：

- 参与者、称谓关系、数量和单复数；
- 动作、受事、方向、目的与因果角色；
- 身体部位、物件类别、植物种类和命名主题；
- 否定、条件、情态、确定度和状态变化；
- POV、人称、speech act、敌意/亲密强度。

对应案例：姜正文 R197 单数变复数、R297“吻”变“打招呼”、R322/R387 确定度变化、R442 等 POV 漂移；崔第三 R2176“不显眼”变“不碍眼”、R2300 一般孕期不适被缩窄为孕吐。

### 8.2 问题跨度与允许编辑跨度

候选应携带 `issue_span`、`allowed_edit_span`、`preserve_spans` 或等价证据。超出已证明问题范围的修改必须提供源文/上下文依据，否则降为人工建议。

姜正文 R82 只需补“我买单”，不应同时把“暖暖身子”改成“清凉解渴”；R297 的“吻”应处于 preserve span。老师 Final 中的偏好改写也不得反向教 Skill 扩大 edit span。

### 8.3 反馈证据状态

反馈资产至少区分：

- `confirmed_error`：review target 已对齐且错误可证明；
- `project_rule_candidate`：可重复项目规范，待确认适用范围；
- `style_preference`：两者均可；
- `source_issue`：源文疑误；
- `conditional`：客户选择或文化决策；
- `teacher_regression`：Final 引入错误；
- `unknown`：空 Note 或无法对齐。

只有 `confirmed_error` 和已确认的 scoped project rule 才能进入 runtime reference。`style_preference`、`teacher_regression` 和空 Note 不进入。

### 8.4 指标拆分

报告不再只给一个“修改率”，而是至少展示：

- exact edit rate；
- 去格式后的 content edit rate；
- issue-backed correction rate；
- project normalization rate；
- editorial rewrite rate；
- reviewer regression count。

章/节标题 100% 改动中 44.9% 只是格式，崔第三 98.7% 改动中只有 58.7% 属于客观问题或项目规范；这两个例子说明单一改动率不可用于评价 LQE。

## 9. 暂缓项

- 不新增后置 QA 阶段或新 worker；
- 不对整句韩语用宽泛 regex 扫描助词；
- 暂不硬拦 `은/는`、`이/가`、`과/와`、`로/으로`；
- 不自动采用老师全部 Final；
- 不把空 Note 当通过；
- 不把 `가고일→석상`、李白意象、西式化等文化选择自动全局化；
- 不在缺 scene/addressee/relationship 证据时仅凭人物名确定敬语；
- 不在本轮反馈分析任务中运行 LQE。
